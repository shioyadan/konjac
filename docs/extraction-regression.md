# 図表・数式の抽出と回帰確認

図表と数式は、本文・見出し・キャプションのブロックを境界として使う。図表はまず段とキャプションの配置から左右の所属を決め、その範囲内の内容を囲む。表を先に確定するため、表の直下にある図が表を巻き込みにくい。空白の許容幅は本文フォントから PDF ポイント単位で求め、2 ポイントのマスクセルとは分離している。

片側の段が図だけの場合も、本文側の段位置とキャプション側の位置を組み合わせて左右の所属を決める。同じ段に複数のキャプションがあっても、それだけで複数段とはみなさない。

表はキャプションの上下を同じ処理で調べ、両側に候補がある場合は近くの横罫線がある側を優先する。罫線で区別できない場合は、複数列の左端・右端・中央が繰り返しそろう行が多い側を選ぶ。同点なら下側を優先する。整列が確認できる行間は空白が広くても探索を継続するが、本文や別キャプションの境界は越えない。表にはキャプションとの間の追加余白を設けず、近接する先頭行・最終行の文字が欠けることを防ぐ。

キャプションの継続は、位置・フォント・行間の共通判定にまとめている。表キャプションの次に同じ高さの複数セルが並ぶ場合は、説明文に取り込まず表の先頭行として残す。一語だけの本文末尾も、直前の本文と位置・サイズがそろえば境界に含める。PDF.js が罫線を単色の画像マスクとして返す場合も図形として扱う。

番号付きの数式は式番号を起点に、近接する式行・添字・罫線を上下へまとめる。左右どちらの番号も扱い、`(2.1a)` のような枝番号にも対応する。等号などの関係記号は必須とせず、番号だけや通常の文章は除外する。本文と別の式番号を境界とするため、隣の式との連結を防ぐ。番号なしの数式は字下げ、上下の余白、記号を併用して保守的に検出する。小さい未分類の数式記号は本文に残す。表を構造化した HTML や数式の TeX への変換は行わず、従来どおり画像として表示する。

入力座標は PDF.js の viewport を使って正規化する。CropBox の原点が 0 でない文書でも、文字・図形・切り出し画像の座標をそろえる。

通常の PDF は描画オブジェクトの bbox を使う。全面画像の PDF では、キャプションのあるページだけを等倍描画し、画素の OR で縮小したマスクを同じ領域検出へ渡す。これによりスキャン文書専用の切り出し推定を廃止した。全ページで描画する案も比較したが、通常の PDF にまで描画時間・メモリを加えるため採用していない。OCR のない画像からキャプションや数式を読む機能は追加していない。

CLI は PDF.js 同梱の標準フォントを読み込み、フォントを埋め込んでいない PDF でも図表画像の文字を描画する。

```sh
make test          # PDF 不要: 合成入力による境界、数式、座標、描画マスクの検証
make regression    # work/*.pdf を既定で4件ずつ並列変換し、実PDFの注釈と比較
make regression REGRESSION_JOBS=2  # 同時に変換するPDF数を指定
make typecheck
make
```

`make regression` は生成 JSON を `/tmp/konjac-regression.*` に置き、出力先を表示する。変換は指定した並列数を上限として実行し、1件でも変換に失敗すると検証全体を失敗にする。既存の JSON を確認する場合は次のコマンドを使う。

```sh
node tests/pdf-regression.cjs /tmp/konjac-regression.XXXXXX
```

`tests/regions.json` は手元の11本の論文から選んだ94領域の注釈。test4・test9 の全28数式で、複数行の式・添字・分数を含む切り出し範囲を確認する。test10・test11 は全25図表を含み、下置きの表キャプション、表とグラフの隣接、短い本文末尾の混入を確認する。test12 は全11図表を含み、片側の段に図が縦に並ぶページで、隣の段の本文による途中切れを確認する。test2・test12 の表はキャプション近傍の先頭行・最終行も確認する。`content` は切ってはいけない内容の内側の矩形 `[x, y, width, height]`、`exclude` は混入してはいけない本文・別の図・ページ装飾上の点。座標は表示ページの左下を原点とした PDF ポイント。キャプション・数式番号との対応、図表141件と番号付き数式28件の維持も確認する。PDF 自体は追加配布しない。

この注釈は代表例の回帰確認であり、全ページの正解領域や一般的な認識率を表すものではない。新しい文書で修正するときは、その失敗例と影響を受けそうな成功例を追加する。機械的な検証に加えて CLI の HTML と、原稿に検出枠を重ねた画像を確認する。

`--debug-mask` は検出に実際に使ったマスクを出力し、`--debug-scan` はキャプションごとの所属範囲・本文で区切った範囲・最終矩形を記録する。
