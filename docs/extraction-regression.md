# 図表・数式の抽出と回帰確認

図表と数式は、本文・見出し・キャプションのブロックを境界として使う。図表はまず段とキャプションの配置から左右の所属を決め、その範囲内の内容を囲む。表を先に確定するため、表の直下にある図が表を巻き込みにくい。空白の許容幅は本文フォントから PDF ポイント単位で求め、2 ポイントのマスクセルとは分離している。マスク側で本文らしさを再推定せず、文字・図形の占有と、共有ブロックから描いた停止領域を区別する。検出時に同じ扱いになる本文候補・図中文字・その他の文字は、一つの文字属性にまとめている。

片側の段が図だけの場合も、本文側の段位置とキャプション側の位置を組み合わせて左右の所属を決める。同じ段に複数のキャプションがあっても、それだけで複数段とはみなさない。短い左寄せキャプションの直上に段をまたぐラスター画像がある場合は、その画像全体まで左右の範囲を広げる。

ページ端の同じ位置に3ページ以上繰り返す柱・ページ番号・フッターは、本文と図表領域の推定から除く。文字列中の数字を正規化して比較するため、記事番号付きのページ番号も扱う。ページ最下部のフッターは2ページでの反復でも除く。

表はキャプションの上下を同じ処理で調べ、両側に候補がある場合は近くの横罫線がある側を優先する。罫線で区別できない場合は、複数列の左端・右端・中央が繰り返しそろう行が多い側を選ぶ。同点なら下側を優先する。整列が確認できる行間は空白が広くても探索を継続し、途中に一列の見出しがある小表同士もまとめる。本文や別キャプションの境界は越えない。表にはキャプションとの間の追加余白を設けず、近接する先頭行・最終行の文字が欠けることを防ぐ。

キャプションの継続は、位置・フォント・行間の共通判定にまとめている。表キャプションの次に同じ高さの複数セルが並ぶ場合は、説明文に取り込まず表の先頭行として残す。一語だけの本文末尾も、直前の本文と位置・サイズがそろえば境界に含める。PDF.js が罫線を単色の画像マスクとして返す場合も図形として扱う。本文の未完の文に同じ書体・行間で続く図表参照は、キャプションから除く。対応する図表領域が見つからない候補も本文に戻す。

番号付きの数式は式番号を起点に、近接する式行・添字・罫線を上下へまとめる。左右どちらの番号も扱い、`(2.1a)` のような枝番号にも対応する。文字化けした番号の正規化、左右の判定、式本体からの番号除去で番号の規則を共有する。等号などの関係記号は必須とせず、番号だけや通常の文章は除外する。本文と別の式番号を境界とするため、隣の式との連結を防ぐ。番号なしの数式は字下げと記号を併用し、番号付きと同じ本文境界の内側で検出する。波括弧と関係記号を持つ場合分けの式は、左端にそろっていても同じ処理でまとめる。小さい未分類の数式記号は本文に残す。表を構造化した HTML や数式の TeX への変換は行わず、従来どおり画像として表示する。

数式に接する一行だけの説明文や、インライン数式を含む本文も境界として扱う。短い説明文は段の位置と本文書体の単語から補い、前後の独立した式がつながることを防ぐ。字下げや行頭の数式を含む説明文も境界にし、隣の段の本文がわずかに重なっただけでは式を除外しない。本文の高さは主なフォントから求め、数式の上下は起点の baseline から区切る。PDFの数式フォントの高さが実際の文字より大きくても、本文を切り出し画像に取り込みにくくする。本文との境界に加えて固定の余白を要求しないため、分数や積分が本文に近接していても検出できる。Unicode 対応のない Type3 フォントは、文字の描画命令と字形ごとの bbox から位置を復元する。元の文字幅が 0、フォント全体の高さが過大な場合も、描画位置から式の範囲を求める。通常のフォントでも制御文字を返す場合は、その書体を文書内で記録し、文字幅とフォントの ascent・descent で画像範囲を求める。括弧の文字対応が壊れた式番号は、独立した「記号・数字・記号」の並びと配置から識別する。記号全般の文字置換は行わない。

本文中の分数・添字・Unicode 対応のない文字は、同じ段・同じ行の前後の文章に挟まる画像として保持する。字下げされた行を別の段と誤認しないよう段の左端をまとめ、字形の中心から所属行を決める。本文・脚注・参考文献それぞれの実際の文字サイズで行を再構成し、本文を捨てて添字だけが孤立することを防ぐ。段落の結合でも主な文字サイズを比べ、脚注が次の段の本文に吸収されることを防ぐ。画像の余白は隣の本文までに制限するが、既知の字形 bbox は切らない。独立したアクセントと、1文字程度の幅に長い文字列が割り当てられた拡張字形も画像へ戻す。数式と横位置が重なる前の行の単語を取り込まず、本文の空きに収まる所属行を選ぶ。拡張字形の上端が baseline として返る場合は、所属行までを画像に含める。キャプションにも同じ処理を使い、CLI・Web版・拡張版・翻訳後の表示で画像を引き継ぐ。翻訳 JSON の `⟦math-…⟧` は数式画像を表すため、そのまま残す。TeX 化や、あらゆるフォントの文字対応の修復を行うものではない。

キャプションのない小表は、短いセルの列位置が3行以上で繰り返しそろうことから拾う。疑似コードは制御文の構文を起点に、字下げされた代入・括弧・コメントをまとめる。どちらも数式と同じ本文境界・領域拡張を使い、独立した画像ブロック（`BLOCK_IMAGE`）として配置を保持する。行全体が本文とは別の等幅フォントであるコマンドや設定行も、代入・オプション・対話プロンプトの構文を起点に同じ処理でまとめる。行間が狭いコードでは、次の本文の ascent を境界に使い、`g` の下端やアンダースコアを切らない。本文行がOCRの僅かな baseline 差や両端揃えの広い空白で分裂した場合は、同じ段の断片を横方向の順序で再構成する。広い空白を越える結合は、書体と baseline がそろう場合に限る。

`Listing N` と `Algorithm N` は、専用のコード型を追加せずキャプション付きの図として画像化する。上下を同じ処理で調べ、近いコード列を段位置・書体・行間でまとめる。行番号が別書体でも同じ行へ戻し、等幅フォントの色分け・太字・字下げ・コメント・空行を画像に残す。複数行のキャプションは図表と同じ規則で連結する。本文の書体へ戻る位置や別キャプションで止めるため、コードの構文解析は行わない。従来の比例幅フォントの疑似コードには、既存の制御文・代入の判定を起点として使う。test2 の Algorithm 1 を回帰領域に含め、Listing は上下のキャプション、行番号、複数書体、隣接する本文・別のListingを合成入力でも確認する。

読み順は段数に合わせる。段間が狭く、最初の行結合で左右がつながっていても、文字断片の間の空白から段間を推定して分割し、左右に独立した本文行があることを確認する。幅の広い本文があり、左右それぞれに独立した行の並びがないページは上から下へ読む。図だけのページはキャプションが少なくても左右の段を維持する。大きな段落先頭文字を本文行へ戻した後にも段分割を適用し、先頭文字のサイズで左右の本文がつながったままにならないようにする。

段落の継続は、実際に段落へ加えた最後の本文行と比較する。図中文字やページ装飾を読み飛ばしてもこの行を失わず、脚注と次の段の本文を文字サイズで分ける。同じ baseline の見出しと本文は左から右へ並べ、見出し直後の短い本文を別の段と誤認しない。段・ページをまたぐ未完の文は継続し、略語の閉じ括弧だけでは文末としない。字下げされた本文は次行の右端も使って折り返しを判定し、短い完結した説明行は分離する。括弧内の数値の折り返しを番号付き箇条書きと区別し、箇条書き後の広い行間では新しい段落を始める。中央のページ番号も繰り返す位置から除き、図内の回転文字は既知の描画範囲で所属を判定する。

段をまたぐ小さい文字の Abstract も文章として残し、同じ書体と行間で続く1語の末尾を捨てない。本文より小さいページ下部の注記には `footnote` を付け、段の移動時に本文へ吸収しない。脚注を挟んで分断された本文は結合して注記を直後へ移し、文献リンクの対象から脚注を除く。参考文献内の著者名を節見出しとして扱わず、番号付きリストの項目を参考文献と誤認して後続段落を取り込むことも防ぐ。

見出しの折り返しは、ページ・行間・書体・左右または中央の整列を使ってまとめる。カンマや疑問符を含む節見出しも認識する。最上部の単独の大会バナーより下に論文タイトルがある場合はタイトル候補を切り替える。著者名はアクセント付きの文字を許容し、同じ列に別の文章が始まったら著者の収集を終える。

箇条書きの記号は、行内数式へ変換する前に本文行へ戻す。既知の中黒・矢印に加え、ピリオドやハイフンとして抽出された記号、Unicode 対応のない小さな丸・四角の字形は、本文との空白と同じ字下げの反復で認識する。通常のハイフンや小さな数式を一律に置換しない。項目の字下げは段左端からの距離をフォントサイズで正規化してノードに保持し、CLI・Web版・拡張版で同じ入れ子のリストへ変換する。図を挟んで残った単独の項目もリストとして表示する。段やページをまたぐ項目の継続は大文字でも許容し、図を挟んで分断された未完の項目も結合する。翻訳と原文表示は各項目の本文を対象とし、子リストの構造を維持する。

文字片・表セル・Listingを行へまとめる処理は、baseline の近さでグループ化する共通処理を使う。表のセル整列は表の検出時にだけ計算する。段の字下げ位置をまとめる処理と、コードに接する本文の ascent から境界を求める処理も共通化している。

入力座標は PDF.js の viewport を使って正規化する。CropBox の原点が 0 でない文書でも、文字・図形・切り出し画像の座標をそろえる。

通常の PDF は描画オブジェクトの bbox を使う。アウトライン化された小さな文字や句読点も残し、図の端が欠けることを防ぐ。全面画像の PDF では、キャプションのあるページだけを等倍描画し、画素の OR で縮小したマスクを同じ領域検出へ渡す。これによりスキャン文書専用の切り出し推定を廃止した。全ページで描画する案も比較したが、通常の PDF にまで描画時間・メモリを加えるため採用していない。OCR のない画像からキャプションや数式を読む機能は追加していない。

CLI は PDF.js 同梱の標準フォントを読み込み、フォントを埋め込んでいない PDF でも図表画像の文字を描画する。

```sh
make test          # PDF 不要: 合成入力による境界、数式、座標、描画マスクの検証
make regression    # work/*.pdf を既定で8件ずつ並列変換し、実PDFの注釈と比較
make regression REGRESSION_JOBS=2  # 同時に変換するPDF数を指定
make typecheck
make
```

`make regression` は生成 JSON を `/tmp/konjac-regression.*` に置き、出力先を表示する。変換は指定した並列数を上限として実行し、1件でも変換に失敗すると検証全体を失敗にする。既存の JSON を確認する場合は次のコマンドを使う。

```sh
node tests/pdf-regression.cjs /tmp/konjac-regression.XXXXXX
```

`tests/regions.json` は手元の15本の論文から選んだ216領域の注釈。test4・test9 の全28数式で、複数行の式・添字・分数を含む切り出し範囲を確認する。test10・test11 は全25図表を含み、下置きの表キャプション、表とグラフの隣接、短い本文末尾の混入を確認する。test12 は全11図表を含み、片側の段に図が縦に並ぶページで、隣の段の本文による途中切れを確認する。test2・test12 の表はキャプション近傍の先頭行・最終行も確認する。test13・test14 は全30図表と番号付き数式5件・番号なし数式14件を含み、ページ見出しや本文の混入、上下に分かれた小表の途中切れ、文字対応が壊れた数式の検出を確認する。test13 の7・9・10・15ページでは、番号なしの総和・分数・積分・複数行の式も確認する。test14 の5ページの定義式、8ページの番号なし数式と、test13・test14 の本文中の分数・積分・添字など11領域も確認する。`inline: true` は本文・キャプション内の数式画像を内容範囲から照合する。test13 の12ページの小表と疑似コード、13ページの疑似コードも範囲を確認する。`blockIndex` はページ内のキャプションなし画像ブロックの順番。数式マーカーと画像の対応、本文の文字化けも検査する。test3 の単語ごとの段落分断、動作モード名と説明の分離、3・5・7ページの等幅コード5ブロックも確認する。test15 は全7図表と番号付き9式・場合分け2式、test16 は全13図表と番号付き16式・等幅コード3ブロックを含む。test15 の式への説明文混入、test16 の複数行数式の途中切れ、段をまたぐ画像の右側欠け、本文中の表参照の誤検出を確認する。test16 の節見出しの順序と段をまたがない本文の連続性も検査する。8文字以下、または2単語以下の短い本文が同じページで3段落以上連続する場合は、表の分解や本文行の分裂を疑ってテストを失敗させる。箇条書きや文末記号付きの短文は除く。この検査は異常の手がかりであり、それだけで画像化を決めるものではない。`content` は切ってはいけない内容の内側の矩形 `[x, y, width, height]`、`exclude` は混入してはいけない本文・別の図・ページ装飾上の点。座標は表示ページの左下を原点とした PDF ポイント。番号なし数式の `equationIndex` はページ内で上から数えた1始まりの順番（番号付きも含む）。キャプション・数式番号・ページ内の順番との対応、図表191件・数式74件・キャプションなしの画像ブロック11件の維持も確認する。PDF 自体は追加配布しない。

この注釈は代表例の回帰確認であり、全ページの正解領域や一般的な認識率を表すものではない。新しい文書で修正するときは、その失敗例と影響を受けそうな成功例を追加する。機械的な検証に加えて CLI の HTML と、原稿に検出枠を重ねた画像を確認する。

段落の回帰では、`prose` に一つの本文ノード内に残す連続文字列、`paragraphStarts` に独立した段落の先頭を指定する。test2 の括弧内の数値、test5 の箇条書き後の本文、test10 の脚注と本文の分離、test11 の行頭見出しと段をまたぐ文、test16 の狭い字下げ領域を確認する。test3 の短い説明行とtest9 の箇条書きも、別々の段落として維持する。

`title`・`author` はメタデータ全体を照合する。`referenceCount` は参考文献の全項目の番号順とリンク先を確認し、test6・8・11・12を対象とする。見出しの折り返し、test15 の番号付きリスト後の段落、test16 の Abstract・段またぎ・脚注末尾、test4 のアクセントとtest16 の平方根・コードの範囲も確認する。`absent` は文字化けなど残してはいけない文字列を指定する。

`lists` は7本から選んだ17リストの項目数・順序・階層を確認する。`items` に項目の先頭文字列を並べ、入れ子は `children`、段・ページをまたぐ連続文字列は `includes` で指定する。test2 の段またぎ、test7 の矢印と図を挟む単独項目、test14 の文字対応のない中黒、test16 の親3項目と子7項目を検査する。test5・test9・test13 の既存リストも対象とし、特に短い数式の項目と文章の項目が同じ階層に保たれることを確認する。

`--debug-mask` は検出に実際に使ったマスクを出力する。`MASK_TEXT` は文字、`MASK_SHAPE` は図形、`MASK_BODY`・`MASK_CAPTION`・`MASK_HEADING` は停止領域、`MASK_CROP` は切り出し範囲を表す。本文の枠線も、実際の停止判定に使ったブロックの矩形を描く。
`--debug-scan` はキャプションごとの所属範囲・本文で区切った範囲・最終矩形を記録する。
